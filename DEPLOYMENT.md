## Сборка и размещение

1. Выполнить `npm ci`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run test:e2e`.
2. После подтверждения и входа владельца в Netlify импортировать подготовленный GitHub-репозиторий. Выбрать Free, production branch `main`, корневой каталог репозитория.
3. Netlify читает `netlify.toml`: build command `npm run build`, publish directory `dist`. `.nvmrc` задаёт Node.js 24. Переменные окружения не нужны.
4. Не включать Netlify Forms: форма сохраняет данные только в localStorage. Дополнительные плагины и серверные функции не требуются.
5. Проверить режим доступа и явно опубликовать сайт без авторизации. Новые проекты Netlify могут первоначально быть приватными. Скопировать фактический production URL; желаемое имя поддомена не считается гарантированно доступным.
6. После успешной публичной проверки добавить реальную ссылку в README и сообщение работодателю.

Альтернатива импорту: после подтверждения загрузить содержимое готового `dist/` как статический deploy. `vite preview` предназначен для локальной проверки, а не для работы публичного сервера.

## Проверка после деплоя

До выполнения этих пунктов не отмечать публичную версию проверенной:

- Открыть production URL в чистом контексте браузера без аккаунта Netlify; по возможности также в приватном окне. Не должно быть формы входа или защиты предпросмотра.
- На 360 и 1440 px проверить загрузку страницы, CSS, изображения (`naturalWidth > 0`), отсутствие горизонтальной прокрутки. Шрифты системные, сетевых файлов шрифтов нет.
- Проверить CTA и подстановку программы из каждой карточки, смену программы в кастомном списке, клавиатуру и закрытие списка.
- Открыть календарь, проверить блокировку фонового скролла, выбор сегодня, закрытие и возврат фокуса.
- Отправить пустую форму и прошлую дату: должны появиться ошибки. Исправить поля.
- С вымышленным именем сохранить заявку на сегодня или будущий день. Проверить детали, обновить страницу и убедиться, что они восстановились на том же origin и в том же контексте.
- Проверить изменение и удаление тестовой заявки.
- Проверить console/error, pageerror, неуспешные сетевые запросы и HTTP-ошибки ресурсов.
- Зафиксировать фактическую ссылку, время и результат. Если есть сбой — исправить и повторить затронутый сценарий.

Данные локального сайта не переносятся на новый домен. В приватном окне заявка должна восстанавливаться после reload внутри того же сеанса; сохранность после закрытия приватного окна не ожидается.
