# Результаты проверки

Дата: 20 октября 2026 года, Europe/Moscow. Проверялась локальная production-сборка на `http://127.0.0.1:4173`, а не опубликованный сайт.

React / React DOM 19.3.1, TypeScript 5.9.3, Vite 7.3.7, ESLint 10.13.0, Vitest 4.1.12, Playwright 1.64.1, axe-core integration 4.14.0. Установленный Google Chrome на macOS, два параллельных тестовых worker. Дополнительно основной сценарий вручную пройден в браузере приложения Codex.

## Проверенные сценарии

- Выбор каждой из трёх программ; замена первой программы второй; смена программы после сохранения.
- Отправка пустой формы: три сообщения у полей, фокус на первом ошибочном поле.
- Имя из пробелов, исправление ошибки при вводе, имена с дефисом и из разных алфавитов.
- Отсутствующая дата, неправильные календарные даты, невисокосный 29 февраля, прошедшая дата; сегодня и будущая дата допустимы.
- Часовые пояса UTC+14 и UTC−9 с несовпадающей с UTC календарной датой.
- Вкладка, оставленная до следующего дня: обновление min и отклонение вчерашней даты при сохранении.
- Двойной клик по сохранению, восстановление после reload, изменение заявки и удаление.
- Отсутствующие данные, повреждённый JSON, неправильная структура/версия, неизвестная программа, старые корректные заявки.
- Недоступный getter localStorage, исключение при записи (quota), исключение при удалении. Успех не показывается при неудаче записи; данные формы сохраняются; неудачное удаление не скрывает заявку.
- Сохранение только четырёх разрешённых полей, отбрасывание неизвестных полей при восстановлении.
- Введённый HTML-подобный текст отображается строкой и не создаёт HTML-элементов. В основном E2E-сценарии исключений `pageerror` не было.

## Найдено и исправлено

1. Первый браузерный запуск: 11 успешных тестов, три падения из-за контраста. Подписи первого экрана имели отношение 4,24:1. Цвет заменён на более тёмный `--muted`; повторный запуск: 14/14, затем расширенный итоговый: 16/16. Правило axe не отключалось.
2. Просмотр скриншотов: неудобный перенос вводного заголовка на узком экране. Размер заголовка адаптирован; новые скриншоты проверены.
3. Просмотр скриншотов: отсутствовавшее разделение фразы перед курсивом в заключительном блоке. Добавлен пробел.
4. Установка сообщила, что ESLint 9 больше не поддерживается. Проверены peer dependencies и выполнено обновление до ESLint 10; повторный lint успешен.

Ограничения среды также были разрешены: первоначальный npm registry не был доступен в sandbox; установка выполнена с сетевым доступом через официальный registry. Запуск loopback-сервера требовал разрешения среды; после него HTTP-ответ — 200. Публикация не выполнялась.

Тестовый runner печатает предупреждение о одновременно установленных окружением `NO_COLOR` и `FORCE_COLOR`. Оно относится к выводу тестовых worker, не к приложению; предупреждение не скрывалось.

Системный календарь зависит от браузера. Автоматический axe не доказывает полное соответствие WCAG.

Перед передачей: подтвердить публикацию, разместить `dist` на HTTPS-хостинге и повторить выбор/сохранение/reload на окончательном origin. По возможности открыть сайт на телефоне, пройти нативный календарь клавиатурой и прослушать ошибки скринридером.


## Обновление формы по обратной связи

Фокус теперь оливковый, 2 px внутрь границы поля (`outline-offset: -2px`), без внешнего отступа и без изменения размеров. Подтверждение не получает декоративную рамку вокруг всей панели; перевод фокуса для озвучивания сохранён.

Добавлены кастомный combobox программ и календарь в modal dialog, без новых зависимостей. Нативное поле даты, min, ручной ввод и проверка при отправке сохранены. На сенсорном устройстве при поддержке вызывается системный showPicker; при отказе используется кастомный календарь.

Дополнительно проверено:

- Прямоугольник поля не меняется при фокусе; computed style — outline 2 px, offset −2 px, цвет rgb(66, 77, 60).
- Список: стрелки, Home/End, Enter, Tab, Escape с сохранением прежнего значения; выбор буквой; закрытие по клику снаружи; раскрытие вверх у края экрана.
- Календарь: запрет прошлых дней, следующий/предыдущий месяц, выбор сегодня, повторное открытие на выбранном дне, Page Down, стрелки, Enter, Escape, замкнутый Tab и возврат фокуса к кнопке.
- Открытые список и календарь: axe на 360, 768 и 1440 px, отсутствие выхода за ширину окна и вертикальное размещение списка.
- Эмуляция сенсорного устройства: вызов showPicker и fallback при исключении. Метод подменялся в тесте; настоящий системный picker физического телефона не объявляется проверенным.
- В браузере приложения вручную просмотрены фокус, раскрытие списка вверх, смена программы и календарь. Введённые пользователем данные в его вкладке не очищались.

Новые проверки нашли уход фокуса при обходе календаря Tab: добавлено явное замыкание Tab/Shift+Tab. Тесты адаптированы к ролям combobox/listbox; старый поиск по label совпадал и с полем, и со списком. Тест ожидает завершения перевода фокуса после карточки; кириллический keydown имитируется явно, поскольку US key map Playwright не отправляет его через keyboard.type. При проверке закрытия щелчок выполняется по видимому заголовку вне выпадающего списка, а не по перекрытому им полю. Утверждения сценариев сохранены.

Скриншоты обновлённой формы: `qa/form-focus.png`, `qa/program-select.png`, `qa/calendar.png`. Реальные телефоны и скринридеры остаются непроверенными. Исходники и ZIP сборки обновлены.


## Блокировка фоновой прокрутки календаря

По замечанию пользователя добавлена фиксация фона на время открытого кастомного календаря. Сохраняются позиция страницы и изменяемые inline-стили, компенсируется ширина скрытой полосы прокрутки. При закрытии стили и координаты восстанавливаются до прежних значений; возврат фокуса выполняется без прокрутки. Внутренняя прокрутка длинного календаря разрешена, scroll chaining ограничен.

Фактические проверки: TypeScript, lint и production build успешны. Пять новых Playwright-проверок прошли отдельно, затем полный прогон — 29/29 за 12,8 с. Колесо мыши над фоном не изменяет положение контрольного заголовка; после крестика, Escape, клика на подложку и выбора дня восстанавливаются координаты и обычная прокрутка. Проверена повторная блокировка при повторном открытии. На 360 × 400 px календарь прокручивается внутри, фон остаётся неподвижным. Скриншот — `qa/calendar-scroll-lock.png`.
