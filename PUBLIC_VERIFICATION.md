Дата: **20.10.2026, Europe/Moscow**. Проверялся именно HTTPS-домен Netlify, а не localhost.

- Сайт: [mesto-spa-ibragim.netlify.app](https://mesto-spa-ibragim.netlify.app/).
- Код: [Ibragim29052003/mesto-spa](https://github.com/Ibragim29052003/mesto-spa).
- Размещение: Netlify Drop, один статический проект на существующем **Free Legacy**. Тариф не менялся, add-ons, функции, базы данных и платные услуги не подключались.
- Runtime-код, тесты и ресурсы после локального аудита не менялись. Автоматического деплоя из GitHub нет: сайт опубликован из проверенного production ZIP.

## Что действительно проверено

Playwright с установленным Chrome, отдельный чистый непостоянный контекст для каждой ширины, без загрузки аккаунтов, cookies или storage state. Дополнительный независимый контекст подтвердил, что предыдущая тестовая заявка туда не переносится. Это изолированные incognito-контексты; отдельное видимое приватное окно браузера вручную не открывалось.

Для HTML точное побайтовое совпадение не заявляется: Netlify добавляет один невидимый служебный HTML-комментарий о хостинге. После удаления именно этого комментария HTML совпадает с dist. Дополнительного исполняемого кода или видимого содержимого в нём нет. JS/CSS/HTML отдаются с Brotli.

Отдельно выполнены **14/14** проверок восстановления календаря: 360/1440 px, Escape, крестик, клик на подложку и выбор дня, повторные открытия. Проверены прежние inline-стили, scrollX/Y и фокус. Тест ждёт обработку нативного события close; первоначальное мгновенное чтение стиля однажды опередило cleanup. Повторная проверка с ожиданием того же результата, как в исходных E2E, подтвердила корректное восстановление. Код календаря не изменялся.

Вручную через браузер приложения на публичном домене: карточка «Перезагрузка» → селект со стрелкой и Enter → «Глубокий отдых» → вымышленное имя → календарь, выбор сегодня Space → Tab/Enter для сохранения → reload и восстановление деталей. После проверки удалена только созданная тестовая заявка. Публичная вкладка оставлена пользователю.

## Найдено после размещения

Netlify по умолчанию вставил Powered by Netlify badge и скрипт HUD. Это отличалось от согласованного дизайна. После явного разрешения пользователя badge отключён настройкой проекта для всех посетителей. Повторные проверки подтвердили отсутствие badge и его скрипта. Новый деплой и изменения CSS для скрытия не потребовались.

Переименование проекта с автоматически выданного имени в `mesto-spa-ibragim` выполнено после отдельного подтверждения точного адреса. Когда управление браузером временно было недоступно, это было раскрыто пользователю; недоступные действия не объявлялись выполненными.

## Безопасность поставки и ограничения

Перед первым push проверены 37 файлов: секреты, типичные форматы токенов/ключей, контактные данные и абсолютные личные пути в текстовых файлах не найдены. Два WebP не содержат EXIF. Git использует публичный GitHub noreply email. Зависимости, отчёты, кэш, dist и .env исключены из Git. В репозиторий добавлен этот Markdown-отчёт; сырые JSON/HTML Lighthouse и скриншоты сохранены отдельно локально.

Реальные iOS/Android, их системные picker UI, озвучивание настоящими скринридерами и полная матрица Safari/Firefox не проверялись. Автоматические оценки доступности не являются сертификатом WCAG. Известных критических проблем в проверенной публичной реализации нет. Проект готов к передаче как демонстрационное тестовое задание.
